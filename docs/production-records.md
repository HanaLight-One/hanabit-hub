# 이미지 제작 기록

이미지 파일은 기존 날짜별 폴더에 그대로 두고, Hub SQLite에는 파일을 찾기 위한
안전한 상대 저장 키와 생성 메타데이터만 색인한다. 절대경로나 이미지 바이너리를
DB에 복사하지 않는다.

## 현재 흐름

1. `state/image-generation-jobs/*.json`의 완료 작업을 확인한다.
2. 작업의 결과 절대경로는 서버 내부에서만 설정된 이미지 루트와 대조한다.
3. 일치하는 이미지의 공개 ID와 상대 저장 키를 `image_assets`에 기록한다.
4. 프롬프트와 선택 정보는 `image_generation_metadata`에 기록한다.
5. 이미지 카드의 제작 기록 API가 허용된 메타데이터만 반환한다.

서버 시작과 제작 기록 조회 시 동기화하므로 Hub에서 만든 완료 이미지는 별도의
수동 입력 없이 웹에 나타난다. 같은 작업을 다시 읽어도 이미지 ID 기준으로 갱신되어
중복 행을 만들지 않는다.

## 웹에서 확인하는 정보

- 사용한 프롬프트 원문: 기본 접힘, Owner Only 화면에서만 표시
- 등장인물 선택 방식과 기록된 인물 ID·표시 이름
- 화풍 선택 방식과 기록된 화풍 ID·표시 이름
- 이미지 앵커 사용 여부
- 생성 목적과 실행 방식
- 생성 시각, 소요 시간과 기록된 재시도 횟수

과거 이미지나 외부 자동 생성 이미지에 구조화된 영수증이 없으면 파일명이나
프롬프트 내용으로 값을 추측하지 않는다. 화면에는 `기록 없음`으로 표시한다.

## API 계약

```text
GET /api/images/:imageId/production-record
```

응답 스키마 2는 프롬프트와 선택 메타데이터를 포함한다. 기존 JSON 제작 기록이
있으면 DB 기록이 없는 이미지에 한해 읽기 호환용으로 유지한다. API는 DB의
`storage_key`, 절대경로, 작업 로그, 외부 API 원문과 인증 정보를 반환하지 않는다.

## 보안과 소유권 경계

- 이미지 ID는 안전한 불투명 식별자다.
- DB의 저장 키는 허용된 이미지 루트 아래의 상대경로만 사용한다.
- 완료 작업의 결과가 설정된 이미지 아카이브 밖이면 색인하지 않는다.
- 프롬프트는 Owner Only 관리자 Hub 전용이며 향후 공개 사이트 API에는 포함하지 않는다.
- 이미지 파일의 이동·삭제·덮어쓰기는 이 색인 과정에서 수행하지 않는다.
